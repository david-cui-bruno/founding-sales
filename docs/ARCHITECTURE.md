# FSS architecture

Written 16 September 2026 against main `abfd259`. It describes what is in the tree, not what is planned: the plan is [`docs/ROADMAP.md`](ROADMAP.md), the release manual is [`docs/engineering/release.md`](engineering/release.md), and superseded designs are under [`docs/archive/`](archive/README.md). Paths are repository-relative.

## 1. Process model

FSS is an Electron 44 application for Apple Silicon macOS with one optional cloud worker and one bundled Swift helper.

| Process | Entry points | Role |
| --- | --- | --- |
| Main (Node 24) | `src/main.ts`, `src/main/startApplication.ts` | Owns the encrypted SQLite workspace, all domain logic, every IPC handler, the delegation runtime, research jobs, backups and the Apple bridge child process. Serves the renderer over the privileged `callie://` scheme (`src/main/protocol.ts`, `src/main/navigationPolicy.ts`, `src/main/contentSecurityPolicy.ts`) and holds the single-instance lock. A reserved backup invocation is detected before any window opens (`src/main/backup/preReleaseBackupRuntime.ts`). |
| Preload | `src/preload.ts`, `src/preload/createCallieApi.ts`, `src/preload/apis/` | Exposes `window.callie` through `contextBridge`: one narrow API object per feature slice plus the health probe. Every request and response is parsed by a Zod schema from `src/shared/contracts/` before it reaches renderer code (`src/preload/ipcClient.ts`). Types in `src/shared/preload.d.ts`. |
| Renderer (React 19) | `src/renderer/main.tsx`, `src/renderer/App.tsx`, `src/renderer/app/FounderApp.tsx` | `App` probes foundation health and shows `src/renderer/foundation/DiagnosticsScreen.tsx` until the encrypted database is ready. `FounderApp` mounts the fixed shell (`src/renderer/app/AppShell.tsx`, `src/renderer/app/navigationItems.ts`, `src/renderer/app/routes.ts`, `src/renderer/app/shell.css`), the command palette, and renders one route through `src/renderer/app/routeRegistry.tsx`. Design tokens and themes: `src/renderer/design/tokens.css`, `src/renderer/design/themes.css`. |
| Delegated worker (AWS Lambda) | `cloud/lambdas/delegated-worker/src/handler.ts` | HTTPS API behind API Gateway with DynamoDB single-table storage (`cloud/lambdas/delegated-worker/src/dynamoStore.ts`), authenticated per pairing (`cloud/lambdas/delegated-worker/src/workerAuth.ts`). It admits owner commands, holds worker-owned company records and campaigns, polls mail and runs the research pipeline on a schedule. It imports the shared contracts and research modules from `src/` by relative path (`cloud/lambdas/delegated-worker/src/index.ts`) and is bundled by `cloud/lambdas/delegated-worker/build.mjs`. Deployed only from `cloud/worker-terraform/`, which calls the module `cloud/terraform/modules/delegated-worker`. |
| Apple bridge (Swift) | `native/apple-bridge/`, `contracts/apple-bridge/v1/protocol.md` | The nested `Callie Apple Bridge.app`, run only as the app's child process and spoken to over JSON Lines (`src/main/appleBridge/appleBridgeSupervisor.ts`, `src/main/appleBridge/appleBridgeClient.ts`). Settings shows it as a gated feasibility panel (`src/renderer/appleSpike/AppleSpikePanel.tsx`). Live call observation is a manual, consenting check only (`docs/engineering/apple-feasibility-procedure.md`). |

The renderer never touches Electron, Node or the network directly; everything crosses the preload boundary. The main process never renders.

## 2. Validated IPC

Every channel is registered through `src/main/ipc/registerValidatedIpc.ts`: `validateSender` (`src/main/ipc/validateSender.ts`) rejects frames not loaded from the trusted renderer URL, the request is parsed with the channel's Zod request schema (or must be argument-free), the handler runs, and its result is parsed with the response schema before it is returned. A handler that opts into `safeErrorCode` never leaks a cause. `src/main/ipc/registerApplicationIpc.ts` composes the application channels over the readiness boundary by calling one registrar per feature: what is left of the legacy person routes (`src/main/leads/registerLeadsIpc.ts`, `src/main/leads/registerLeadDetailIpc.ts`), the company model (`src/main/workspace/registerLocalWorkspaceIpc.ts`, `src/main/today/registerDailyIpc.ts`), and `src/main/recovery/registerRecoveryIpc.ts`, `src/main/health/registerHealthIpc.ts` and `src/main/ipc/registerShellIpc.ts`. The Pipeline, Conversations, Learnings, Friday, Inbox review, CSV import, legacy Today, discovery and S3 sourcing registrars were removed with their routes in Batch 6. Delegation and the outreach providers are registered by `src/main/ipc/registerOutreachIpc.ts`; LinkedIn, phone setup and the bridge panel by `src/main/linkedin/registerLinkedInIpc.ts`, `src/main/communications/registerPhoneSetupIpc.ts` and `src/main/appleBridge/registerAppleSpikeIpc.ts`.

Channel and preload inventories are exact and enumerated. When you add a channel or a preload member, update all of: `tests/integration/preload.test.ts` (preload surface), `tests/main/registerApplicationIpc.test.ts` and `tests/main/localWorkspaceIpc.test.ts` (registered channels, counts and slice windows), `tests/integration/continuityPublicRoutes.test.tsx` with `tests/fixtures/continuityDomainFixture.ts` (registered outreach channels), `test/verifySecretsPreloadInventory.test.mjs` (the preload inventory the secret scan trusts) and `tests/integration/appleSpikePreload.test.ts`. Any automatic renderer call, even a local one, also breaks the "queue nothing" allowlists in tests that mount the parent component; grep for `toEqual([])` before reporting.

## 4. Delegation runtime: owner commands and worker events

`src/main/delegation/delegationRuntime.ts` (`createDelegationRuntime`) is the desktop half of the worker. A pairing (`src/main/delegation/pairingStore.ts`, safeStorage-protected credential redeemed at `POST /pairing/redeem`) gives it an HTTPS client (`src/main/delegation/executionClient.ts`). Every desktop write is an **owner command** from `src/shared/contracts/ownerCommandContract.ts`: `bootstrap-selected-account`, `refresh-selected-account-record`, `campaign-command`, `prepare-manual`, `complete-manual`, `approve-reply`, `submit-approved-reply`, `approve-requested-followup`, `configure-owner`, `report-acquisition-milestone` (and `approve-meeting`, whose desktop producer is being removed). The flow:

1. The renderer calls `window.callie.delegation.*` (`src/preload/createCallieApi.ts`), which lands on an `outreach:delegation-*` channel in `src/main/ipc/registerOutreachIpc.ts`.
2. The runtime binds the command to the current owner state (`expectedAuthorityGeneration`, `expectedVersion`), stores it in `delegated_commands` (`src/main/delegation/delegationRepository.ts`) and POSTs it to `/commands`. The receipt is `pending`, `applied` or `rejected` (`src/shared/contracts/delegationContract.ts`). A retry after an uncertain result reuses the same `commandId`, and `POST /commands/reconcile` asks the worker about a command it may already hold; command identity is never re-minted.
3. The worker (`cloud/lambdas/delegated-worker/src/ownerCommandCoordinator.ts`, `cloud/lambdas/delegated-worker/src/commandService.ts`) authenticates the pairing, checks scope and version, applies the command transactionally in DynamoDB and appends **worker events**.
4. `src/main/delegation/delegationSync.ts` (`synchronizeDelegation`) flushes the local outbox, then pages `GET /events?cursor=` and applies each event to the local projection (`delegated_applied_events`, threads, meetings, campaigns) with a transactional cursor. A gap or an incomplete page means the owner view is not current; `ownerFresh` is reported honestly and never assumed.
5. Reads that need worker authority go to `POST /accounts/preparation` (`cloud/lambdas/delegated-worker/src/accountPreparationRead.ts`, `src/shared/contracts/accountPreparationContract.ts`). Local reads never claim worker authority.

Saving or approving is never sending, calling or booking. The manual channels (call, LinkedIn) end in a `prepare-manual` handoff and a founder-reported `complete-manual` outcome; nothing in the product dials or posts. Google access is a worker-side grant (`cloud/lambdas/delegated-worker/src/remoteGoogleAuthorization.ts`, `/google/*`) that the desktop only begins and reads. Route parity between the handler and the Terraform API is asserted by `tests/infrastructure/delegatedWorkerRouteParity.test.ts`.

## 5. Research and discovery

**Desktop: one company per explicit run.** Company research is a command on a selected saved company. `src/main/research/companyResearchWorker.ts` claims one `pm_account_research_jobs` job, snapshots the account, fetches only approved HTTPS pages on the company's own host (`src/main/research/companyPageProvider.ts`, `src/main/research/companySourcePolicy.ts`), extracts quoted facts (`src/main/research/companyFactExtraction.ts`) and admits them as evidence with a receipt. `src/main/research/guidedCompanyDiscoveryProvider.ts` refuses any run whose limits are not `maxCompanies === 1`, and `src/shared/contracts/localCompanyResearchSettingsContract.ts` requires the same, so there is no bulk firm discovery on the Mac today. Configuration is in Settings (`src/renderer/foundation/LocalCompanyResearchSection.tsx`) and the flow is described in `docs/known-company-extraction.md`.

**Worker research pipeline.** The same research modules run inside the worker (`cloud/lambdas/delegated-worker/src/researchCoordinator.ts`, `cloud/lambdas/delegated-worker/src/researchCycle.ts`, `cloud/lambdas/delegated-worker/src/researchProduction.ts`, `cloud/lambdas/delegated-worker/src/sourceCoordinator.ts`) under owner-approved budgets and reservations (`cloud/lambdas/delegated-worker/src/discoveryReservationStore.ts`, `cloud/lambdas/delegated-worker/src/researchSetup.ts`; desktop side `src/main/delegation/researchSetupService.ts` and `src/renderer/foundation/ResearchSetupSection.tsx`). It is off by default and every paid step is reserved before it is spent. Neither path produces the automatic morning list yet; that is roadmap priority 2.

**Legacy prospect discovery** (`src/main/discovery/`, `src/main/domain/discovery/`) assesses retained source evidence into the Today shortlist. It belongs to the person model.

## 6. Storage and backup

- One encrypted SQLite file per profile, `callie.sqlite3`, with the key envelope `callie.key-envelope.json` beside it under Electron's user-data directory (`src/main/applicationPaths.ts`). Driver `better-sqlite3-multiple-ciphers` (`src/main/db/sqliteDriver.ts`) with a fixed cipher profile (`src/main/db/sqliteDriverDecision.ts`) verified on every open (`src/main/db/databaseEncryption.ts`). The 32-byte workspace key is protected by macOS Keychain through Electron `safeStorage` (`src/main/security/safeStorageKeyProtector.ts`); there is no plaintext fallback, and the app refuses to mint a replacement key when any database or interrupted-conversion artifact exists.
- `src/main/db/plaintextDatabaseUpgrade.ts` converts a pre-encryption schema-1 file with fsynced sibling markers and never deletes the only validated copy.
- `src/main/backup/backupService.ts` writes verified `daily`, `manual` and `pre_release` copies into the profile's `backups/` directory with receipts in `backup_receipts` (`src/main/backup/verifiedBackup.ts`; retention in `src/main/backup/backupRetention.ts`). `npm run backup:pre-release` (`scripts/createPreReleaseBackup.mjs`) launches the packaged app in a reserved mode that takes the lock, copies, verifies and exits without opening a window. Holds and prerequisites: `docs/engineering/release.md`.
- Provider and pairing secrets live in safeStorage-protected stores (`src/main/delegation/pairingStore.ts`, `src/main/outreach/providers/credentialStore.ts`), never in the database and never in the renderer.

## 7. Tests and gates

Where tests live:

- Root vitest (`vitest.config.mts`, `npm test`): `tests/main/` (main-process units and repositories), `tests/integration/` (real route, real domain, disposable encrypted database, and the worker handler harness), `tests/renderer/`, `tests/shared/`, `tests/infrastructure/` (Terraform source checks, route parity) and colocated `*.test.ts(x)` under `src/`. Some files import worker source, so the Lambda lockfiles must be installed first (see `README.md`).
- `test/*.test.mjs`: release tooling (marker, package verifier, secret scan, backup host). Two run under `node --test` as `npm run test:helpers:node`; the rest are vitest files.
- `tests/browser/*.spec.ts`: Playwright Chromium against real renderer components (fixtures in `tests/fixtures/`), 1440 and 1050 wide, light and dark. `npm run test:browser:native-desk` is the CI group; the other specs run in the local combined gate.
- `tests/e2e/*.spec.ts`: packaged-app end-to-end with a temporary `--user-data-dir` (`npm run test:e2e`, helpers in `tests/support/`). Production founder data is never read by tests.
- Worker: `cloud/lambdas/delegated-worker/test/` via `npm test` in that package; `npm run verify:lambdas` runs every tracked Lambda package in name order, today only `delegated-worker`, discovered from their manifests. Swift: `npm run test:swift` (`native/apple-bridge/Tests`).

Gates:

- **CI** (`.github/workflows/ci.yml`, hosted macOS, every PR and push to `main`): `verify:secrets`, `typecheck`, `lint:tracked`, `test`, `test:browser:native-desk`, `test:helpers:node`, `verify:lambdas`, `build:operational-tools`, then `verify:secrets` again over generated output.
- **`verify:release`** (`scripts/verifyRelease.mjs`): the local release gate. Typecheck, lint, root tests, the browser group, Swift, helper tests, the synthetic Electron backup-host test, all Lambda gates, one package, package verification (`scripts/verifyPackage.mjs`), history and package secret scans (`scripts/verifySecrets.mjs`), packaged E2E against that same artifact, then marker and clean-HEAD checks (`scripts/writeReleaseMarker.mjs`). David runs it himself before an install. Manual: `docs/engineering/release.md`.
- **Release workflow** (`.github/workflows/release.yml`): exact-SHA, dispatch-only, gate not publication.
- **Combined lane gate** (coordinator, per batch): root `npm run verify`, worker test, typecheck and build, `verify:secrets`, the browser group plus the extra browser specs, on the merged candidate.
