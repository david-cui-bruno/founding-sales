# Versioned evidence and PostgreSQL processing

The approved broader CRM spec #479 retains versioned source evidence and durable human decisions, with rebuildable claims, summaries and retrieval projections processed through existing PostgreSQL jobs. This reuses current fencing, transactional effects and paid-attempt controls instead of introducing a workflow engine or full event sourcing; deletion and current access can invalidate content across all projections. A bounded PostgreSQL hybrid-retrieval prototype is authorized for evaluation, while production vectors and hosted processing remain conditional on their own checks.

Ask worker stages and scoped deletion acquire one workspace transaction advisory lock before identity, request, job and spending locks. Recovery must conserve a dispatched reservation even after private source authority is erased; relying on original-source locks would prevent that recovery or reverse deletion's lock order. A two-session registered-worker/public-deletion regression reproduced that deadlock and verifies this ordering. Verifier and provider waits happen outside transactions. Direct source invalidation retains the existing source-first order, while window insertion locks its request parent before checking the current generation; immutable windows require no update privilege.
