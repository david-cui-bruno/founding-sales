# Lean automatic releases with maintenance

October11,2026: David accepts ordinary startup crashes, failed jobs, temporary unavailability, imperfect AI and hours of repair; preserve protections against lost business history, unintended sends and cross-person data exposure. Merges should automatically deploy application changes and explicitly eligible routine migrations after proportional CI. Reuse strict-schema stop→migrate→start maintenance releases rather than building permanent staging or zero-downtime compatibility now. Destructive/privilege/unknown changes need one concrete review, including the current88→99 backlog.

CI selects affected suites and dependent consumers, with shared/unknown-path broad fallback, real deployed-baseline database upgrade checks and broad main regression. Codex verifies actual product/worker/UI outcomes; David reviews a few meaningful outputs for usefulness. Internally automate immutable image/release records and checks rather than asking the owner to coordinate receipts. One shared release serialization and visible partial-failure status remain; reconcile ambiguous writes and use forward repair when an old binary is schema-incompatible. ECS rollback is not migration rollback.

#580 implements this prospective workflow and its narrow reviewed migration identity. Current release/sending holds remain until specifically lifted through the revised supported flow; this ADR does not authorize the existing backlog rollout or cloud-role changes. Deployment preserves owner configuration under ADR0009 and does not grant new data, funding, recipients or outreach scope.
