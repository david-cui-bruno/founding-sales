# G1: provider lock files are not committed yet

**Date:** 19 September 2026 · **Lane:** G1 infrastructure · **Spec silence:** the specification says nothing about `.terraform.lock.hcl`.

`infra/.gitignore` excludes `.terraform/`, `.terraform.lock.hcl`, `*.tfstate*` and `*.tfvars`.

Ordinarily a Terraform lock file should be committed: it pins the exact provider versions and their checksums. Two reasons it is not committed here, both temporary:

1. **Platform coverage.** A lock file generated by `terraform init` on this machine records `darwin_arm64` hashes only. CI runs on `ubuntu-24.04`, and a single-platform lock file makes CI fail with a checksum mismatch. Producing a correct multi-platform lock needs `terraform providers lock -platform=darwin_arm64 -platform=linux_amd64 ...`, which is a network operation whose output nobody on this lane can review against a deployment.

2. **Repository convention.** `cloud/worker-terraform/README.md` already says: *"Keep provider downloads and lock files in disposable scratch directories until a deployment provider lock file is reviewed and pinned."* This lane follows that rather than inventing a different rule for the new tree.

The version constraints are still pinned in configuration — `hashicorp/aws ~> 5.60` and `hashicorp/google ~> 6.0` in every `versions.tf` — so an unreviewed major version cannot appear.

**Before the first production apply**, generate and commit a multi-platform lock file for both roots:

```bash
cd infra/roots/production
terraform providers lock \
  -platform=darwin_arm64 \
  -platform=linux_amd64 \
  -platform=linux_arm64
git add .terraform.lock.hcl   # and remove the ignore entry in infra/.gitignore
```

Review the recorded versions and hashes at that point, and drop the `.terraform.lock.hcl` line from `infra/.gitignore`.
