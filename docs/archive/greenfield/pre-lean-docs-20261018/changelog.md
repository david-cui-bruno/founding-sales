# FSS changelog

Frozen 26 Sep 2026. From here the changelog is the list of merged pull requests (`gh pr list --state merged`).

The lines below, newest first, cover 21 to 26 September 2026. Those from 21 to 25 September were seeded from the release records 8.0 to 8.0av, one line each; the bracketed number ending each names its record in `release-records.md`.

- 2026-09-26 PR 252 (R1): `infra/scripts/rollback.sh` rolls production back to a previous release's images in one command (release.md 4.1a): it plans the checked-out previous commit with its digests and ranges, keeping sending, the generation pin, hostname, certificate and alert e-mails as production runs them, and with `--apply` applies, deploys on the rolling path and smokes; it refuses digests not tagged for that commit, a database version outside its ranges, a service mid-rollout, and any plan touching more than task definitions and the two services.
- 2026-09-26 PR 251 (D1): "Edit as a new draft" on a published version that still has a LinkedIn step now makes the draft instead of failing with `invalid_input`: the draft keeps the email and call steps in order, numbered 1..n, and leaves the LinkedIn step out; a version of only LinkedIn steps gives an empty draft, which Publish refuses until a step is added; and a refused draft no longer leaves an empty draft behind.
- 2026-09-26 PR 249 (T1): a rehearsal teardown no longer leaves a retained 20 GB automated backup of its database (the rehearsal root deletes them with the instance; production keeps its 35 days), and the prefix guard no longer fails on deleted EC2 security groups and rules the tagging API still lists — it sets them aside like ECS and KMS ARNs, while a real leftover such as an RDS snapshot still fails it.
- 2026-09-26 PR 248 (coordinator): the images run fails its first attempt when `fss-rh-<image>:ci-<commit>` already exists, so another writer's push can never become this run's build (a re-run of the same run still reuses its own tag); `schema-preflight-0018.sh` exits non-zero when ECS refuses to deregister its temporary operations revision, naming the revision to remove by hand. Review of PRs 246 and 247.
- 2026-09-26 PR 247 (A4): migration 0018 takes LinkedIn out of the database — each contact's LinkedIn URL moves into the contact's title, where the Mac shows it; the migration refuses, naming counts, before it would erase a stored LinkedIn message or recorded reply unless the owner has said so (`--remove-linkedin-history`); `infra/scripts/schema-preflight-0018.sh` prints those counts while production is still running (schema 18, a stop-migrate-start release: release.md 4.3)
- 2026-09-26 PR 246 (A1): an automatic deploy now starts only when the Greenfield gate and the Source security gate (each found by its workflow file) are green on the images commit and that commit is still on main. It waits up to thirty minutes with no credential, otherwise says `manual` with the reason, and checks again before its first write and before the record put. It deploys only digests from the images run's own artifact whose images that run pushed. A change to `schemaRange.ts`, `migrationRunner.ts` or `queryable.ts` takes the manual path. A rollout counts only once ECS calls it COMPLETED and every running task has the new digest, which `deploy.sh current` now requires too. No IAM change
- 2026-09-26 PR 245 (A2): a sequence with a LinkedIn step stored before 25 September no longer makes the Mac's sequence editor say it could not read the versions — the step is one greyed, uneditable row, "LinkedIn step (channel removed 25 Sep 2026)", a draft still holding one cannot be published until it is saved without it, and "Review and resume" shows such a step held for channel removed and leaves it held; publish the desktop after the API deploys
- 2026-09-25 PR 244 (a3): the changelog is one fragment file per pull request, `docs/greenfield/changelog/<yyyy-mm-dd>-pr<n>.md` (or `<yyyy-mm-dd>-<branch-slug>.md` before the number is known) holding the one line that used to go at the top of `changelog.md`, so two open pull requests no longer conflict over it; `npm run changelog` folds merged fragments into `changelog.md`, and `npm run changelog:check`, in the gate and the nightly, refuses a malformed fragment or a `changelog.md` edited by hand
- 2026-09-25 PR 243 (g99): the daily alarm digest can now be created in production — its function's settings are encrypted with the environment's own key instead of the AWS-managed Lambda key the deployment role may not use; the next apply adds the function and its 07:00 schedule and nothing else
- 2026-09-25 PR 242 (g100): the CI deploy now puts the release record for the digests it deployed, after the smoke passed (`deploy.sh ci record` on the operations task, from the green gate run on the images commit), and the owner's sending attestation may name the release process, `"releaseGateReference": "ci-gate:main"` (any ci-gate record naming the running image), so sending stays on across automatic deploys; a record that is not put fails the run red with one line and the new worker holds until it is put by hand (release.md 4.0). The operator sets four repository variables from the production root's new `ci_deploy_*` outputs, and `fss-prod-ci-deploy` gains `ecs:RunTask` on the operations family in the production cluster and `ecs:TagResource` only as part of it.
- 2026-09-25 PR 241 (g101): merges are unblocked after 20:00 New York time — the dial replay test now pins the instant it consumes its ticket at, instead of using the wall clock, and a new case pins the rule it tripped over: a ticket issued at 19:59:30 local and consumed at 20:00:10 local is refused as outside the calling window; no production change
- 2026-09-25 PR 240 (g97): a rehearsal dispatched with its defaults is the trimmed schema run (create, migrate and deploy, the schema ranges, the smoke, destroy; about 45 minutes, no release record); the full run with the restore drill and the release record is `mode: full` and runs on the first Sunday of each month from *Greenfield monthly restore drill* instead of weekly; and applying production while a rehearsal runs no longer fails it, because its last guard compares only the rehearsal's own resources
