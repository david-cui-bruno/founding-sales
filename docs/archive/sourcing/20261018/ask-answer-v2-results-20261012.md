## What the results establish

**Contract expressibility:** both models correctly answered both SQL-only cases in both repetitions. The four strict outputs per model supplied empty original-citation arrays and failed the current original-required grammar. All corresponding prose answers correctly used exact references. This is a demonstrated interface mismatch, not fabricated counts or missing retrieval. The documented abstention-plus-exact-display carveout was not followed in these raw generations; host display alone cannot be counted as a valid native Claim.

**Interpretation:** both Sonnet formats, in both repetitions, promoted the reserved coverage note's tentative later texts to known messages and/or equated unknown other-channel coverage with not captured. Sonnet strict additionally excluded the discovery-stage West pilot from a revision request without evidence; prose retained ambiguity but added unsupported weighting toward East. Haiku had more conditional-offer, report-certainty and identity/pilot errors in this sample. Prose improved its usefulness but did not remove critical failures.

**Wording:** SQL prose produced direct short answers such as “There are 2 open opportunities recorded for Alder Example.” Other prose still exposed window codes, repeated provenance qualifications, included unnecessary summaries or retained awkward wording. A prose output mode does not by itself deliver the intended conversational UX.

**Cost and input:** strict rows used about 39,000 input tokens per model across 24 calls versus about 12,000 for prose. The factor includes schema/tool exposure and necessary completion instructions, not just JSON syntax. Sonnet's prose median was under three seconds here. This supplied-context sample does not justify a larger model or prove whole-product latency.
