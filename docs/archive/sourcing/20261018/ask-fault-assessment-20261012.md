## What primary research contributes

AI SDK documents tools as model-visible descriptions and input schemas with optional execution. Its structured output API combines tool use and schema-validated generation. Those mechanisms establish data shape and execution plumbing; they do not certify that a prose claim follows from a cited source. Changing from a final-answer tool to structured text is therefore an interface hypothesis, not an SDK-prescribed semantic repair. Current docs describe current APIs, not proof that Callie's pinned version needs migration. [Tool calling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling), [structured data](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data).

Anthropic's agent guidance recommends starting with simple solutions and investing in tool descriptions, formats and boundaries. That supports examining the synthesis interface before adding orchestration complexity; it supplies no causal evidence against Callie's durable jobs or capture design. Its original article also notes that its tooling landscape has changed. [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents).

Anthropic's evaluation guidance distinguishes the model-plus-harness system from the evaluation harness, recommends multiple trials, balanced tasks and known working reference solutions, and treats code, model and human grading as complementary. ALCE separately evaluates fluency, correctness and citation quality. Together these sources support separating valid references from supported interpretations; their results are not Callie reliability estimates. [Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), [ALCE](https://aclanthology.org/2023.emnlp-main.398/).
