# Approved opening selection

The worker selects one explicitly approved opening line for the first email of a current campaign, then prefixes the unchanged approved baseline body. This is bounded selection, not generation of arbitrary subject/body/offer/pricing/promises. Existing campaign authority and source lifecycle remain in ADR0013/0016.

`campaignOpeningInterpretation` uses only the existing Bedrock Haiku route. It projects public firm name/locality/region, approved variant IDs/text and current opaque citation IDs; no recipient, private note, message, raw page, binding or attempt metadata enters the prompt. Input is bounded to16KiB, output256tokens and one strict approved variant/citation object. Foreign/free-form/truncated/malformed/expired choices refuse; no alternate-provider fallback or retry.

`budgetedCampaignOpeningSelector` runs only after the existing opening owner commits its durable UNKNOWN claim. It uses the existing shared research/credit budgets and a `campaign_opening` reservation, with fixed model/token shape enforced by migration0146. Token count and generation are outside transactions. Send gate precedes research/spend locks; the reservation is marked calling and committed before generation. Exact source/policy/owner/eligibility is checked around waits; a final single-statement owner/clock/zone snapshot follows source waits before invocation; final research holds, lowered budgets and original reservation date/zone remain binding. Already-attempted requests cannot count/call again. Known usage settles once; missing/ambiguous usage conserves the reservation. A lost/thrown model result leaves original UNKNOWN and never remints. Source erasure and final publication checks remain with the existing opening owner.

Bootstrap derives the port from the worker’s existing approved classifier transport. Missing/noncredit transport keeps policy-enabled work held. Ordinary execution eligibility, including stored ownerOFF, is checked before selection. This installs no credential, IAM grant, setting switch, scheduler, email engine or campaign. Browser opening approval does not claim synchronous worker/model health; operational observations belong in current-state.

Controlled adapter/paid/worker checks and actual app_runtime PostgreSQL upgrade/selection/accounting/concurrency tests verify software. A separately invoked bounded fictional model evaluation can establish only the evaluated selection quality. No CI test uses a real model or mail provider. Existing signed admission/composition/dispatch and manual incoming original→edit→preview evidence is retained, not replayed unchanged.

Sending staysOFF throughout Step3. A real recipient email is not an engineering acceptance gate. Real campaign/content approval and later owner activation remain separate; neither opening-policy approval nor model usefulness changes those controls. Automatic incoming replies, booking and coaching remain deferred.
