# Current US prepared research and retained legacy policy

Current prepared-business inputs and targeting proposals can represent the fifty US states and DC, with a nonblank locality. This is source support, not acquisition, automatic admission or channel authority. Existing approved query records, source attempts, Apollo acquisition/table limits and campaign regions are unchanged.

The [current candidate schema](../../packages/contracts/src/sourcing.ts) is distinct from the frozen `legacyCandidateInputSchema`. Current intake, source reads/corrections and qualification use `isCurrentPreparedCandidatePayload`; strict admission, calling, verified-Firm publication and retained recovery retain `isLegacyCandidatePayload`. `qualification-v5`, its prompt and `isTargetGeography` are unchanged. The default pre-phone `nativeFirmEvidence` keeps its legacy behavior.

[Current US geography](../../packages/domain/sourcing/currentUSBusinessGeography.ts) derives the native interpretation from the exact candidate geography. Previously supported target areas keep `native-firm-eligibility-v1`; added coverage uses `native-firm-eligibility-us-v1`. New coverage requires positive first-party service-area evidence with a literal city followed by its full US state name. A code such as CA alone establishes no country. Missing, non-US, provincial, mismatched, ambiguous, negative or conditional evidence remains unavailable. This performs no geocoding or external lookup.

[Current native citations](../../packages/domain/sourcing/nativeFirmEligibility.ts) retain the existing identity, full-block role, first-party host, residential-management, contradiction and freshness checks. [Prepared email fit](../../packages/domain/sourcing/currentPreparedEmailFit.ts) accepts only a revalidated same-input us-v1 native proof, reuses the existing independent business-email route checks and preserves every other unknown/conflict. It returns source-fit and `channelAuthority:not_granted`, never a modified email-fit-v2 verdict or authority to override suppression, owner OFF or admission. The old geographic path and its proof fingerprints remain identical.

[Automatic source authority](../../packages/domain/sourcing/automaticResearchAuthority.ts) still requires the exact retained source, current approved targeting query/policy or exact supported Apollo origin. Current geographic support never substitutes for those bindings. [Publication/read](../../packages/domain/sourcing/automaticResearch.ts) stores the native interpretation explicitly and requires an exact expected version match on current reads and refreshes. A stored legacy-v1 publication cannot be reinterpreted as added US coverage. New-coverage fingerprints bind that interpretation; legacy fingerprints remain unchanged.

[Migration147](../../packages/domain/db/migrations/0147_current_us_prepared_supply.sql) adds only the native-policy metadata column with a legacy default, the closed supported-version constraint and immutable-version constraint trigger. It updates no old business/evidence row. Existing source/owner/candidate/run/identity, expiry, hold, budget, cap and UNKNOWN gates remain.

Focused [pure checks](../../packages/domain/test/sourcing/currentUSPreparedSupply.config.ts), [populated146 upgrade cases](../../packages/domain/test/db/migration0147.test.ts) and [current app-runtime publication cases](../../packages/domain/test/sourcing/currentUSPreparedSupply.pg.test.ts) cover this seam. Database cases require Root's disposable runtime allocation. Source completion or fictional tests do not establish live prepared yield, permission to acquire another source, current endpoint eligibility or contact readiness.
