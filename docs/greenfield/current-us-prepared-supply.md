# Current US prepared research and retained legacy policy

Current prepared-business inputs and targeting proposals can represent the fifty US states and DC, with a nonblank locality. This is source support, not acquisition, automatic admission or channel authority. The October29 approved national rollout preserves existing query records and source attempts, adds48queries to12existing rows through the accepted150 rollout, and retains Apollo limits, search quotas and campaign regions.

The [current candidate schema](../../packages/contracts/src/sourcing.ts) is distinct from the frozen `legacyCandidateInputSchema`. Current intake, source reads/corrections and qualification use `isCurrentPreparedCandidatePayload`; strict admission, calling, verified-Firm publication and retained recovery retain `isLegacyCandidatePayload`. `qualification-v5`, its prompt and `isTargetGeography` are unchanged. The default pre-phone `nativeFirmEvidence` keeps its legacy behavior.

[Current US geography](../../packages/domain/sourcing/currentUSBusinessGeography.ts) derives the native interpretation from the exact candidate geography. Previously supported target areas keep `native-firm-eligibility-v1`; added coverage uses `native-firm-eligibility-us-v1`. New coverage requires positive first-party service-area evidence with a literal city followed by its full US state name. A code such as CA alone establishes no country. Missing, non-US, provincial, mismatched, ambiguous, negative or conditional evidence remains unavailable. This performs no geocoding or external lookup.

[Current native citations](../../packages/domain/sourcing/nativeFirmEligibility.ts) retain the existing identity, full-block role, first-party host, residential-management, contradiction and freshness checks. [Prepared email fit](../../packages/domain/sourcing/currentPreparedEmailFit.ts) accepts only a revalidated same-input us-v1 native proof, reuses the existing independent business-email route checks and preserves every other unknown/conflict. It returns source-fit and `channelAuthority:not_granted`, never a modified email-fit-v2 verdict or authority to override suppression, owner OFF or admission. The old geographic path and its proof fingerprints remain identical.

The current extraction entrypoint in [citation selection](../../packages/domain/sourcing/qualificationCitationRoles.ts) uses the same [scoped service-area predicate](../../packages/domain/sourcing/scopedServiceArea.ts) as native reads. A weak city headline/address cannot suppress a unique, exact, named descriptive residential-management citation. Preserve every original selection, ambiguity refusal and30fact bound. This improves future extraction only. The existing retained-reader entrypoint preserves its original supplementation/ceiling behavior; native reads still require retained role facts, never optional supplements or rewritten historical runs. Email/legacy/source gates remain separate.

[Automatic source authority](../../packages/domain/sourcing/automaticResearchAuthority.ts) requires the exact retained source, immutable acquisition policy and an identical currently approved query tuple, or the exact supported Apollo origin. An additive/ranking policy change keeps the original source object and fingerprint; transient current-policy epochs independently fence publication and reads after waits. Changed/withdrawn queries, malformed acquisition policy, erased associations and native URL ambiguity refuse. Current geographic support never substitutes for those bindings. [Publication/read](../../packages/domain/sourcing/automaticResearch.ts) stores the native interpretation explicitly and requires an exact expected version match on current reads and refreshes. A stored legacy-v1 publication cannot be reinterpreted as added US coverage. New-coverage fingerprints bind that interpretation; legacy fingerprints remain unchanged.

It updates no old business/evidence row. Existing source/owner/candidate/run/identity, expiry, hold, budget, cap and UNKNOWN gates remain.
