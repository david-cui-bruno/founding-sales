## Chosen implementation seam

Introduce one current, opt-in prospect-priority read interface beside the existing manual-list owner. Its request contains filter and bounded pagination context; its response contains the permitted prospect, independent fit/value/timing/role facts or unknowns, closed reason codes with source/date references, next research/review action and continuation context. Keep existing strict list contracts and exact subject lookup available unchanged for historical clients and migration fixtures. Both current list consumers use the same owner; React renders recommendations rather than scoring records.

The domain owner composes existing source/identity authorization with deterministic ordering before pagination. Optional evidence loss clears derived reasons and recomputes priority without hiding an otherwise permitted raw prospect. Pagination must either preserve its ordering context or explicitly require refresh after relevant changes; silently drifting offset pages is insufficient. Do not load an unbounded pool and perform full evidence/phone projection for every row.

Use small sourcing modules for ordering and its storage/projection, plus narrow existing CRM adapters for evidenced roles. Avoid growing the already large CRM evidence-decision module or adding a provider framework. No model, capture or external IO belongs in a list read. Persist only necessary identifiers, revisions, policy/reason metadata and timing through normal source-retention owners; do not copy original prose into an analytics ledger.

## Build sequence and verification

1. Define current priority/role/consideration contracts and storage with a deterministic coverage policy. Specify the maximum ordinary-lane consideration gap and pagination invalidation behavior in tests before claiming fairness. Record deliberate consideration, never list refresh. Keep skipped/wrong-number filters explicit and available.
2. Implement the domain read/consideration commands and role annotations, preserving principal/source/revision/expiry fences and genuine event deduplication. A missing Person produces research work, not a new Firm/Person or channel grant.
3. Wire Prospects and retained Calling to that interface. Show reasons, unknowns, role hypotheses and next action without changing Today urgency or prepared-proof selection. Exact reload, correction and held-command recovery remain intact.
4. Preserve selection-time hypotheses using minimal metadata; extend existing outcome/report owners only where structured observations actually exist. Show unavailable measures as unavailable. Include considered/selected denominators and observation windows; first-contacted cohorts alone cannot measure selection yield.
5. Verify a mixed pool larger than one page, deterministic ties, bounded ordinary coverage, refresh/reload, duplicate signals and source/role/principal changes. Reuse manual-list/API/browser lifecycle tests, adding changed-path PostgreSQL and signed controlled browser acceptance. Stored role/selection data requires privacy/migration review; then normal CI, paused-sending release, applicable PITR, smokes and independent readback.

No additional product decision is required from David to start this engineering work. Human original-backed fit judgments/qualification attestation and genuine customer learning remain separate unfinished Step1 outcomes. Email stays OFF; contact, spend, capture, source and UNKNOWN controls remain. No accepted Step2/Step3 verification or scheduling is restarted.
