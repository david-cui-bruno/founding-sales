# Vertex qualification

Prepared-prospect qualification (one model call per company, `sourcing.qualify`) calls Google `gemini-3.8-flash` on Vertex AI, funded by the GCP credits on billing account "Framewise Health Main". Nothing else moved: opening selector, reply classifier, research extraction, calls, meetings, social and CRM stay on Bedrock, `FSS_MODEL_TRANSPORT=bedrock` and `research_settings.model_name` (`claude-haiku-4-5`) are unchanged.

## How it works

- Model constants: `packages/domain/sourcing/qualificationModel.ts` (`gemini-3.8-flash`, provider key `google_vertex.sourcing_qualification`, price table). `settings/funding.ts` funds provider kind `google_vertex` from credits, so `readCreditSpend`, the credit ceilings and the $50/day credit-model cap apply unchanged.
- Endpoint: `https://aiplatform.googleapis.com/v1/projects/colormyworld-prod-dc824/locations/global/publishers/google/models/gemini-3.8-flash` (`countTokens`, `generateContent`). The model answers only at location `global`.
- Request: temperature 0, JSON `responseSchema`, thinking budget 1,024 tokens, `maxOutputTokens` 4,096 (reasoning counts against it and is billed as output). One attempt, never retried; timeouts 20 s (count) and 75 s (generate). Vertex's `countTokens` ignores the response schema, so the reservation adds a fixed allowance (`QUALIFICATION_SCHEMA_TOKEN_ALLOWANCE`, larger than the measured gap). The reservation is priced at the highest rate in force within an hour of its database instant (`qualificationReservationCents`), so a call settling after the 1 January 2027 price change is never under-reserved; settlement prices the actual instant. A 4xx is settled at zero (not billed), a timeout, 5xx or unreadable answer at the estimated cost.
- Credentials: no key anywhere. The worker task role `fss-prod-worker-task` is exchanged at Google STS through a workload identity pool restricted to that role, then impersonates `callie-qualification@colormyworld-prod-dc824.iam.gserviceaccount.com` (only `roles/aiplatform.user`). Non-secret configuration reaches the worker as `FSS_VERTEX_PROJECT`, `FSS_VERTEX_LOCATION` and `FSS_VERTEX_CREDENTIAL_CONFIG`, built by Terraform in production only (`infra/modules/stack`). Without them no qualification is scheduled, and a run that starts finishes `credit_route_unavailable`; there is no Bedrock fallback. Worker start logs `qualification_model` (`configured`, `vertex_unset`, `FSS_CLASSIFIER` when the operator OFF switch stops it, or the variable that is wrong).
- Prompt version `qualification-context-v7` is unchanged. The model name is part of the run fingerprint, so a Claude interpretation is never reused for Gemini; candidates move to Gemini as the 7-day refresh requalifies them.

## Price

Source: https://cloud.google.com/vertex-ai/generative-ai/pricing (Gemini 3 table, global endpoint), read 1 November 2026. Per million tokens: $0.75 input and $3.75 output (reasoning is output) through 31 December 2026; $1.50 and $7.50 from 1 January 2027. Haiku 4.5 on Bedrock is $1.10 and $5.50, so Gemini is cheaper only until the end of 2026. The table steps at `GEMINI_STANDARD_PRICE_FROM` (2027-01-01T00:00Z); revisit the model choice before then. Credit eligibility of Vertex Gemini spend is not verified by this repo: confirm in the Cloud Billing credits page that the credit applies to `Vertex AI` SKUs of project `colormyworld-prod-dc824`.

## One-time setup (operator, in order)

1. GCP side, run by Root: `infra/scripts/gcp-vertex-qualification-setup.sh --dry-run`, then without `--dry-run`, as a GCP account with `roles/iam.workloadIdentityPoolAdmin`, `roles/iam.serviceAccountAdmin` and `roles/resourcemanager.projectIamAdmin` (Owner is enough). It is idempotent: it creates pool `fss-prod-aws`, AWS provider `fss-prod-worker` (account 326255650484, condition `…assumed-role/fss-prod-worker-task/`), the service account and its two bindings, then prints what it granted.
2. Release through the reviewed infrastructure procedure ([lean release workflow](lean-release-workflow.md#reviewed-infrastructure-or-protected-changes)), never a local `terraform apply` or a separate deploy: after this source is on `main` with a green images run, dispatch `greenfield-deploy.yml` in `review_prepare` mode with that exact images run; review that the saved-plan manifest adds only the three `FSS_VERTEX_*` worker task-definition variables (rehearsal gets none) bound to the worker image of that run; then one protected `production-release-review` approval runs the exact `reviewed` job, which applies that saved plan and rolls out the image together. `test/ops/terraformCrossChecks.check.ts` keeps the script's names and Terraform's equal. Releasing before step 1 leaves qualification finishing `credit_route_unavailable` until it lands.
3. Leave `FSS_CLASSIFIER` on: `off` stops qualification too, with or without a classifier transport (start log `qualification_model: FSS_CLASSIFIER`).
4. Smoke from a workstation with application-default credentials: `node --experimental-transform-types scripts/vertexQualificationSmoke.ts "Firm|City|ST|https://site/,https://site/about"` (two real billed calls of a cent or two each). After deploy, confirm one real run ends `selected` with `provider_key=google_vertex.sourcing_qualification`.

## Rollback

Set `FSS_CLASSIFIER=off`, remove the three `FSS_VERTEX_*` variables, or release the previous image, each through the same reviewed procedure: qualification stops cleanly. Reverting to Bedrock needs a code change; there is deliberately no switch.
