# Actionable desktop notifications — #447

The approved seams are the public notification domain/worker and authenticated API against real local PostgreSQL with controlled time; the desktop operation/UI boundary; and a controlled native delivery adapter. They cover current source identity, user-wide deduplication, device attempts, current context routing, all-hours eligibility and honest receipt state. They do not establish production delivery, a backend release or signed desktop publication. No real native alert, provider operation or sending activation is part of these checks.

Notifications consume the versioned Today action projection and its exact current-target validation. Acknowledgement belongs to the notification ledger; it never answers a reply, resets its business-day deadline or removes overdue Today work. Reply reminders use Today's workspace timezone and current holiday calendar. The first overdue reminder is emitted once; there is no repeated reminder cadence. Calls have one reminder in the fifteen minutes before their current start. A different current start is a different occurrence. Resolved, reassigned, superseded, cancelled or rescheduled sources invalidate the old context.

Event deduplication is user-wide within a workspace, across devices. A durable attempt records the device before the native call. Observed native show and human acknowledgement are different facts. A failed native submission is distinct from an unknown outcome. Offline/unavailable is reported by the desktop transport rather than invented as a backend delivery receipt. Restart recovery inspects existing native history and records uncertainty when absence cannot prove failure; it never blindly repeats a show. Routine healthy work stays quiet, and eligibility has no hour-of-day filter.

The installed and pinned Electron version is 44.4.5. Its [Notification API](https://www.electronjs.org/docs/latest/api/notification) exposes stable request IDs, native `show`/`click`/`failed` events, and macOS `getHistory()` for delivered notifications still in Notification Center. Calling `show()` on a restored history object removes the existing notification and posts another; recovery must attach listeners without showing it again. An unsigned macOS build can fail to show and can return empty history, so empty history is not proof that a prior attempt failed. [Electron's notification tutorial](https://www.electronjs.org/docs/latest/tutorial/notifications) describes application setup requirements. No notification permission or credential setting is changed here.

On macOS a cold-start click is available in [Electron's ready launchInfo](https://www.electronjs.org/docs/latest/api/app#event-ready) as a [NotificationResponse](https://www.electronjs.org/docs/latest/api/structures/notification-response). Only the default open action qualifies: Apple documents [UNNotificationDefaultActionIdentifier](https://developer.apple.com/documentation/usernotifications/unnotificationdefaultactionidentifier?language=objc) separately from dismiss. Reading the installed Apple UserNotifications framework constants without submitting any notification yielded `com.apple.UNNotificationDefaultActionIdentifier` and `com.apple.UNNotificationDismissActionIdentifier`. Root captures ready synchronously before whenReady, buffers only a validated stable identifier, and gives it to the current identity's pump. Windows-only handleActivation is not the macOS path. Native userInfo, body and caller-supplied targets never authorize navigation.

Ledger metadata contains source/action IDs, phase, exact typed target, device and attempt IDs, and observed timestamps only. It contains no reply body, excerpt, address, generated draft, access token or native error text. Shared migration numbering waits for #445's minimal 0065; this lane owns 0066 only after that coordination.
