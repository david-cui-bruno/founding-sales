# Ask grounding mechanisms — October 12, 2026

## Decision to make

Keep the existing AI SDK, host-executed read-only tools, PostgreSQL worker and source/access/deletion controls. Test a small change in **answer construction**, rather than changing retrieval architecture or repeatedly expanding prompts: render bounded CRM facts and attribution from host-owned values; let the model summarize source content; require explicit evidence dependencies for each interpretation. Consider one bounded evidence-aware verifier only if residual free-text errors justify its latency and spend.

This is a research recommendation, not an implemented contract or quality result. No paid calls, production operations, activation or sending changes were performed. Release preparation and independently ready capture/exact-state work can proceed alongside this work. The release hold and sending safeguards remain unchanged.

## What the repository actually establishes

Inspected source baseline: `86c5d48d620234e4db182d59bd94a441df16feb0`. The [actual contextual-guidance report](ask-evidence-precision-results-20261012.md) records Sonnet publishing five answers: three useful, one unsupported anonymous-author role and one materially incomplete mixed original/SQL citation. The historical-stage problem did not recur once; that is not repeat-run reliability.

The relevant source was already available in both remaining failures. `apps/worker/src/providers/askAgentSdk.ts` already gives global, output-schema and evidence-specific instructions against the mistakes. `askModelEvidence.ts` already labels selected notes as unverified text and separates executed CRM observations. `handlers/askAnswer.ts` validates citation membership, refreshes exact observations before publication and explicitly labels generated claims `cited_unverified`. It does not determine whether every factual clause is entailed by its references.

Therefore the observed failures are answer attribution and evidence binding after retrieval. Vectors may improve different retrieval failures, but they cannot by themselves force a model to preserve anonymous authorship or cite already supplied SQL. This diagnosis does not prove retrieval is otherwise sufficient.

The proposal respects ADR0002's PostgreSQL projections, ADR0008's private history/current evidence closure and ADR0009's superseding lean owner consent and provisional-quality policy. No stronger correctness label should be assigned merely because the new schema validates.

## Primary research and implementation evidence

**Typed output is a structural guarantee.** AI SDK supports schema-validated output combined with tools; output generation consumes a step. This is suitable for a richer answer plan, but a string that passes Zod may still invent an author or omit a dependency. Our existing explicit `emit_answer` tool already supplies structural constraints. Replacing it with another structured-output API alone would not address the semantic gap. [AI SDK structured data](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data), [tool calling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling).

**Citation completeness and correctness are separate.** ALCE evaluates fluency, correctness and citation quality separately. Its evaluation implementation checks sentence support against the joint cited passages, then checks whether individual citations contribute rather than merely existing. That is a useful evaluation pattern for mixed original/SQL interpretations. Its NLI model remains an approximate judge, and its public tasks are not our CRM workload. [ALCE paper](https://aclanthology.org/2023.emnlp-main.398/), [evaluation source](https://github.com/princeton-nlp/ALCE/blob/main/eval.py).

**Native citations improve pointers, not business truth.** Claude's citation API extracts cited text and guarantees valid pointers to supplied documents; the provider reports better relevant-quote selection than prompt-only citation. Current documentation also says native citations cannot be combined with structured-output JSON. Our Bedrock strict output-tool path is not demonstrated compatible simply because documents can carry citations. A separate prototype would have to establish transport, custom SQL-observation documents, deletion mapping and semantic performance. Valid pointers still cannot prove anonymous identity or an inference's entailment. [Claude citations](https://platform.claude.com/docs/en/build-with-claude/citations).

**A popular citation engine is not a semantic firewall.** LlamaIndex's `CitationQueryEngine` creates citation chunks and configures an LLM response synthesizer with citation QA/refinement templates. It is useful evidence organization, but the inspected implementation does not supply a deterministic claim-entailment gate. Migrating frameworks would reproduce much of the mechanism we already have. [LlamaIndex citation implementation](https://developers.llamaindex.ai/python/framework-api-reference/query_engine/citation/).

**Evidence-aware revision is a credible optional stage.** RARR researches support and post-edits unsupported content while trying to retain the original answer. Its public implementation demonstrates a revision pipeline, not a proof of factual correctness. For Callie, research must stay inside the already authorized source/SQL scope, not fall back to web search or manufacture support for an initial claim. [RARR paper](https://aclanthology.org/2023.acl-long.910/), [authors' implementation](https://github.com/anthonywchen/RARR).

**Self-critique is not automatically verification.** Self-RAG trains models with retrieval/reflection tokens and reports gains on its evaluated tasks; it is not equivalent to adding “check yourself” to a hosted model prompt. Research on intrinsic self-correction finds failures without external feedback in its reasoning setting; it does not establish that every evidence-grounded verifier fails. Together these support testing an evidence-aware judge, not assuming either guaranteed correction or universal impossibility. [Self-RAG](https://arxiv.org/abs/2310.11511), [intrinsic self-correction study](https://arxiv.org/abs/2310.01798).

**Hermes and OpenClaw offer harness lessons, not CRM quality evidence.** Hermes separates metadata search from content extraction, normalizes results and truncates/stores longer content. Its memory tool maintains curated files as session-start snapshots. OpenClaw's citation tests attach file/line references to surfaced recall snippets. These support explicit retrieval results, provenance and predictable context handling. The inspected files do not show a per-clause semantic support guarantee for commercial CRM answers; neither repository's popularity proves that capability. [Hermes web tools](https://github.com/NousResearch/hermes-agent/blob/main/tools/web_tools.py), [Hermes memory](https://github.com/NousResearch/hermes-agent/blob/main/tools/memory_tool.py), [OpenClaw citation tests](https://github.com/openclaw/openclaw/blob/main/extensions/memory-core/src/tools.citations.test.ts). These moving-main sources were inspected on the date above; pin inspected upstream commits before reusing code.

## Mechanism comparison — proposed fit, not measured improvements

| Mechanism | What the host can guarantee | Remaining failure/cost | Fit and recommendation |
| --- | --- | --- | --- |
| Host-rendered exact facts | Rendered names, stages, counts, observation times and SQL citations come directly from a still-authorized executed result. No model rewrites those fields. | SQL itself may be wrong/incomplete; record selection may be ambiguous; unsupported surrounding prose can still smuggle in facts. | Strong first step for existing `read_exact`. Reuse current result hashes and freshness checks. No additional inference call required. |
| Host-rendered attribution | Known/unknown/report-only identity labels come from the source contract; unknown does not become a person or firm team in host-rendered text. | A model-authored proposition could still contain “we/the team”; choosing a typed subject does not constrain arbitrary text. | Strong for attribution UI and source quote blocks. Do not claim it solves free prose unless speaker attribution is structurally owned or separately checked. |
| Evidence-specific answer construction | An answer plan selects permitted observation fields, original spans and typed relationship operators; host constructs citations from those selections. Mixed nodes can require both evidence families. | Model may select irrelevant evidence or the wrong operator. Unrestricted summary/inference text remains probabilistic. Overly large operator vocabulary becomes brittle. | Prototype a minimal algebra: exact observation, original statement/quote, interpretation with explicit premises. Keep flexible summaries visibly unverified. |
| Evidence-constrained generation | Exact quotes can be checked as substrings; exact values and attribution are host-rendered; unknown references and missing declared dependencies are rejected. | Substring presence does not prove context/meaning. Regex/entity scanning cannot prove that pronouns, paraphrases or hidden implications are supported. | Useful deterministic checks for defined fields; do not build a universal semantic parser or silently replace bad prose. |
| One bounded verifier/repair | Host validates verifier output shape, evidence identifiers and budgets; one stage can compare each clause with only its cited support. | Entailment verdict is still model judgment; false passes/refusals and correlated model errors remain. Additional tokens, latency and one or two calls. | Optional after construction ablation. Start with verification/refusal, not recursive rewriting. A repair requires independent recheck and new source/cancellation authority checks. |
| Pragmatic model routing | Explicit configured model/purpose and per-call spend remain conserved. Deterministic paths need no model. | A cheaper/stronger model can still make semantic mistakes; silent fallback changes approved scope. | Keep exact rendering model-free. Evaluate Haiku for ordinary summaries and Sonnet for genuinely ambiguous synthesis only if labeled results justify it. No general winner from five familiar cases. |

Attaching every executed SQL result to every claim is not a repair: it hides missing reasoning and may overcite unrelated records. Replacing “the team” with “the note” by global string substitution is also not a general fix: supported speakers and embedded quotations could be changed incorrectly.

## Smallest useful next implementation

The integrator should first choose between two bounded options, both within current modules:

1. **Construction first (preferred experiment):** retain tool investigation, replace a limited part of `emit_answer` with typed exact-fact references and source-attribution fields, render those fields on the host, and keep source interpretations separate. Never claim the unrestricted body is deterministic. Mixed interpretations carry explicit original and exact premises; the host refuses missing required premise families but cannot infer that a declared premise is relevant.
2. **Verifier first (smaller contract change):** keep current output, add one evidence-aware support check whose inputs include the candidate and only cited canonical evidence/observations. It returns supported/unsupported/uncertain per clause. Publish supported portions or a useful deterministic fallback; report refusals honestly. This directly exercises the existing source without a large renderer, but adds inference and cannot guarantee semantic truth.

Do not implement both blindly. Replay the existing failed outputs offline to measure what each mechanism can actually detect, then use the ordinary configured worker journey to establish behavior. Root owns the shared publication contract. A source-only answer must remain usable without SQL; an exact-only answer must remain usable without original windows. Inferences are allowed and are not converted into confirmed facts. Deletion, narrowed scope, stage changes, cancellation and uncertain paid acceptance remain authoritative after waits.

## Evaluation that can decide instead of prolonging tuning

Freeze the old failures plus unseen variations: anonymous first-person source, named reported speaker, shared endpoint, quoted third party, two conflicting originals, conditional offer, exact stage changed during generation, SQL fact omitted from one mixed clause, irrelevant SQL overcitation and an inference with unsupported causality. Include useful supported examples so an always-refuse gate cannot win.

Record separately: answer usefulness, forbidden author invention, exact-state factual correctness, claim-level support completeness, irrelevant citation rate, refusal/partial rate, tool/call count, latency and conserved allocation. Review complete answers and premises, not only schema-valid publication counts. For a verifier, label false passes and false refusals separately. Compare unchanged baseline with one mechanism at a time on identical frozen evidence and approved model configuration; do not convert a familiar synthetic pass into representative quality.

No fresh model allowance follows from this note. Actual comparison needs the concrete frozen source, labeled cases, limits and owner-approved purpose/spend. Independently ready release/capture work need not wait for that comparison; affected hosted Ask acceptance remains pending until its useful supported behavior is observed.
