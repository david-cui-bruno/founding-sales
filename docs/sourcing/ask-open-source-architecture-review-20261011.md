# Ask architecture: primary-source open-source review

Date: October 11, 2026. Scope: readonly Ask over authorized retained business evidence. This is an inspected-source comparison, not an executed upstream benchmark, paid model evaluation or architecture approval. No runtime, provider, deployment, activation or sending changes were made.

## Finding

The inspected projects support a model using tools inside a bounded host-controlled loop. They do **not** support making the model discover an unfamiliar corpus solely by guessing exact keywords, treating a tiny step cap as universally sufficient, or assuming a valid citation proves a correct interpretation. The closest transferable architecture is efficient scoped retrieval/context preparation plus optional agent investigation and a reserved answer-generation stage. There is no evidence here that Callie needs to replace PostgreSQL, its jobs, or AI SDK with another framework.

This recommendation is an inference from the implementations below, not a measured best architecture. Repository popularity and vendor descriptions are not quality evidence. Current upstream source was pinned when inspected; moving official docs may describe a later release than the installed package.

## Hermes: make discovery and context navigation available

Hermes `session_search` exposes four shapes: keyword discovery, contextual scroll around a message, direct session read, and browse with no query. Discovery uses SQLite FTS5; the tool returns real database messages without another model call. The source caps read-message content at 2,000 characters, scans a bounded candidate set, deduplicates lineage and excludes certain non-user session sources. It specifically documents large-message context blowups and ranking noise from repeated automation sessions. This is directly relevant to Callie's unfamiliar-corpus and repetitive-history problems. [Pinned session-search implementation](https://github.com/NousResearch/hermes-agent/blob/1fd18277267152893a8a24792b79213e7ca3f899/tools/session_search_tool.py).

Transfer the interface pattern, not its identity/filter policy: allow browsing bounded previews, discover candidates, then obtain surrounding canonical conversation context. Callie's newly merged `browse_history` addresses the absence of query-free discovery, but a preview's first window can still omit relevant content. Browsing catalog order is not relevance or recency. Raw personal-session lineage is not a substitute for independent people, historical firm relationships or original copied-source authorization.

Hermes' constructor permits effectively unlimited iterations by default (`sys.maxsize`); a helper entry point separately defaults to ten. Those are configuration choices rather than a universal agent standard. [Pinned runtime constructor/helper](https://github.com/NousResearch/hermes-agent/blob/1fd18277267152893a8a24792b79213e7ca3f899/run_agent.py).

Its `handle_max_iterations` appends a summary instruction and makes an additional summary request, with one retry if empty. This illustrates reserving a usable termination path instead of merely crashing at a ceiling. It also illustrates why blindly copying the pattern would violate Callie's hard allowance: finalization and retry are paid requests that must be reserved and counted. [Pinned iteration-finalization implementation](https://github.com/NousResearch/hermes-agent/blob/1fd18277267152893a8a24792b79213e7ca3f899/agent/chat_completion_helpers.py).

The grounded-citations skill uses a source ledger and literal evidence attachment, with checks for cited sources lacking evidence. It is an optional skill workflow, not proof that every Hermes response receives semantic entailment validation. Literal quote occurrence and ledger membership establish provenance; neither alone establishes that a quote supports the interpretation. [Pinned grounded-citations skill](https://github.com/NousResearch/hermes-agent/blob/1fd18277267152893a8a24792b79213e7ca3f899/skills/research/grounded-citations/SKILL.md).

## Onyx: a search tool can do substantial retrieval work

The inspected Onyx search implementation builds keyword and semantic/original-query branches, deduplicates queries, executes searches in parallel and combines ranked chunks using weighted reciprocal-rank fusion. It merges neighboring/overlapping sections, limits the model-facing context and creates a citation mapping. User-facing document results and the smaller model-facing context are separate. This is a concrete alternative to spending one model round on each low-level search operation. It does not mean Callie should copy its full index infrastructure or perform fresh external acquisition during Ask. [Pinned search implementation](https://github.com/onyx-dot-app/onyx/blob/d6f2ee08f993e955dc72921e3a92ce7c69bc56d0/backend/onyx/tools/tool_implementations/search/search_tool.py).

Its pipeline constructs access filters independently of the model and validates user-selected document-set access before building downstream index filters. A model's proposed query or filter does not create permission. Callie should retain this separation and continue validating current original-source access after external waits and before publishing. [Pinned search-filter pipeline](https://github.com/onyx-dot-app/onyx/blob/d6f2ee08f993e955dc72921e3a92ce7c69bc56d0/backend/onyx/context/search/pipeline.py).

Onyx's dynamic citation processor maps detected citation numbers to returned documents and formats/streams links. The inspected processor is a presentation and mapping mechanism; it is not a proof that every cited sentence is semantically entailed by the document. Preserve Callie's canonical window IDs and current hashes, and measure interpretation separately. [Pinned citation processor](https://github.com/onyx-dot-app/onyx/blob/d6f2ee08f993e955dc72921e3a92ce7c69bc56d0/backend/onyx/chat/citation_processor.py).

## OpenClaw: hybrid recall and graceful partial results

The inspected built-in engine documentation describes SQLite FTS5/BM25 and vector search, with local deterministic ranking and MMR diversity. It explicitly distinguishes MMR from learned relevance reranking. Semantic timeout can return already available keyword results with a partial warning; transcript hits require fresh visibility checks. Slow native queries use a separate readonly process and cancellation terminates the query rather than retrying it on the gateway thread. These are useful designs for latency, cancellation and truthful coverage; the documented claim that hybrid gives the best results is not a benchmark of Callie's corpus. [Pinned built-in-memory documentation](https://github.com/openclaw/openclaw/blob/491dfa6b1597e99ddd246fe3e1f10a1a01c76f65/docs/concepts/memory-builtin.md).

The citation helper emits file-path/line-range provenance and allows on/off/auto presentation, with auto omitting citations in some group/channel contexts. That default is unsuitable for Callie's evidence-backed interpretation contract. We should transfer source locators and fresh visibility checks, while retaining mandatory canonical citation validation and explicit unknown identity/coverage. [Pinned citation helper](https://github.com/openclaw/openclaw/blob/491dfa6b1597e99ddd246fe3e1f10a1a01c76f65/extensions/memory-core/src/tools.citations.ts).

## LangGraph and Letta: runtime structure does not remove domain work

LangGraph's official recursion-limit page distinguishes accidental cycles from legitimately complex graphs; increasing the limit is an option, not a guarantee of progress. Its pinned managed values expose `IsLastStep` and `RemainingSteps`. The transferable mechanism is remaining-budget awareness and intentional termination. We do not need to add LangGraph to obtain it; Callie's host already supplies remaining model generations. Graph recursion limits and Callie's model-generation count must not be compared numerically as equivalent units. [Official recursion-limit guidance](https://docs.langchain.com/oss/python/langgraph/errors/GRAPH_RECURSION_LIMIT), [pinned remaining-step implementation](https://github.com/langchain-ai/langgraph/blob/799c2f04fd3a56186e24e9fb8bbf3568e543cfbe/libs/langgraph/langgraph/managed/is_last_step.py).

Letta documents durable messages, tool calls, runs and steps, plus in-context memory blocks that agents can edit and old messages retrievable after eviction. This provides a useful context hierarchy. In Callie, original observed communications remain authoritative sources; model-maintained summaries/preferences must remain interpretations with provenance and deletion dependencies. Replacing canonical evidence with editable memory would create a different product and undermine historical attribution. [Official stateful-agent concepts](https://docs.letta.com/v1-sdk/concepts/stateful-agents).

## What this implies for Callie

Current source is a host-controlled readonly loop: worker code permits 1–32 generations, while the latest synthetic evaluation chose three; it reserves complete composed inputs, dispatches one SDK generation at a time, executes validated tools under frozen scope and rejects unsupported output. The adapter now advises finalization on its last permitted generation, and bounded corpus browsing is available. Three is not an architectural necessity, and prompt advice alone does not guarantee no last-turn tool request. [Worker implementation](../../apps/worker/src/handlers/askAnswer.ts), [SDK adapter](../../apps/worker/src/providers/askAgentSdk.ts).

Recommended candidate design, subject to reconciliation and proportional evaluation:

1. **Resolve intent/scope and exact state in the host.** Exact commercial/task dates and sending state come from authenticated SQL reads. Ambiguous identity stays ambiguous. Do not make semantic retrieval invent exact state.
2. **Prepare useful authorized evidence efficiently.** Selected short sources can be read directly. Broad history questions need scoped search and previews, then focused context expansion. Put query fusion, deduplication and result packing inside the retrieval boundary; model choice should not control permissions.
3. **Use optional investigation, with a separately reserved final generation.** A straightforward answer should not require many discovery rounds. A multi-hop question may legitimately require more. Before dispatching another investigation round, ensure finalization budget remains. Limit repeated identical queries, total input/output, deadlines and cost independently. Finalization cannot silently add an unapproved call.
4. **Return useful partial answers when supported.** Distinguish cited partial findings, explicit lack of sufficient evidence, retrieval timeout, source changes and formatting failure. Do not convert no matches into a universal negative or partial retrieval into complete history.
5. **Validate format and provenance in software; evaluate semantics separately.** Structured output, current canonical IDs/hashes and exact quotes are necessary transport/evidence checks. They cannot tell us whether a conditional offer is a commitment, a quotation is current intent, or a cited answer is useful.

A model comparison should hold retrieved evidence fixed first, so harness defects are not mistaken for model weakness. Then compare complete strategies: deterministic scoped retrieval plus one answer, the bounded agent, and an efficient hybrid-retrieval-plus-agent candidate. Measure evidence recall, supported-answer quality, identity/time/negation errors, valid abstention, model rounds, latency and conserved cost. This is a discriminating acceptance comparison, not an attempt to rediscover all of retrieval research. The parent model-selection research should determine candidate models and actual provider support before any paid comparison.

## ADR compatibility and decisions still needed

Keeping PostgreSQL canonical evidence, worker processing, AI SDK and readonly tools is compatible with the approved architecture. Reusable retrieval can remain a domain boundary without introducing a new orchestrator/database. Agent-editable business truth would conflict with [ADR0002](../adr/0002-versioned-evidence-and-postgres-projections.md)'s evidence/projection model; allowing shared addresses or corrected present relationships to rewrite historical speaker/context would conflict with [ADR0003](../adr/0003-preserve-original-conversation-context.md). Temporal interpretation additionally needs the approved current-versus-historical promise labels; the ADR alone does not define that classifier. Dropping citations or treating corpus summaries as permanent replacements conflicts with ADR0006/0008's original-copy lifecycle and dependent-content erasure. Broad shared personal memory or bypassing owner scope would conflict with ADR0009's consent/account/source controls. Preserve these decisions unless explicitly reconsidered.

No upstream source establishes an optimal step count, Haiku sufficiency, pgvector superiority on this corpus, or successful Callie extraction. The next decisions are whether finalization is a hard reserved stage, how much broad-history evidence to prepare before the first model call, and which quality/latency/cost target should govern model routing. Release hold, sending safeguards, activation scopes and consumed allowances remain unchanged.
