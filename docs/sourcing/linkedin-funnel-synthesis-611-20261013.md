## Proposed vertical slices, not published implementation tickets

1. **Standing-policy publication:** once the concrete account/content/cadence policy is agreed, owner save/revoke → draft validation → policy-bound queued post → final account/content/policy recheck → native receipt or truthful unknown/cancel state. Preserve existing exact-action fingerprints without requiring David to approve each post. Actual installed/native acceptance stays separately owned by the existing delivery outcome.
2. **Supported connection request:** selected person/firm/profile evidence → bounded policy authorization/reservation → registered desktop request → durable observed/pending/unknown result and revocation/restart protection. Include account-wide/per-action limits in this complete path rather than prebuilding a large quota platform. No guessed profiles, silent identity joins or automatic withdrawal/re-invitation workaround.
3. **Intro DM with reply stop and David handoff:** allowed connection/recipient state → approved content policy → fresh identity/reply/opt-out check → at-most-once send/inspect → incoming reply/opt-out observation → suppress pending recipient work and show actionable original context to David. Depends on the relevant supported target/account/action contract, not all capture/Ask/native roadmap outcomes. Source and adapter readback feasibility must be established, not presumed.
4. **Narrow booking logistics, only if selected:** explicit call agreement → approved link or verified slot/calendar/capacity → scoped logistical message/appointment → matched booking/prospecting stop/Today readback → authorized reschedule/cancel. Broad routine replies and autonomous calls stay off. Calendar/booking decisions remain independent of choosing a posting cadence.

These are candidate slices, not authorization to operate. Existing guarded email, retained prospect-loss reproduction and disabled email readiness remain independently actionable under their applicable scope. Email-domain association requirements are not mechanically transplanted to LinkedIn endpoints.
