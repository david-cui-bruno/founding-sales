# FSS Whole-Product Repair Program

User approval: 2026-09-10 03:04 UTC, “go ahead,” following the written adversarial audit and the recommended repair-only approach.

**Binding design:** [Adversarial product audit](../engineering/2026-09-10-adversarial-product-audit.md). The approved direction is to repair existing behavior, preserve data and useful workflows, move the existing Native Today presentation to one application root, and verify actual route/workflow joins. This is not a new visual redesign or permission to activate live services.

## Invariants

- No broad rollback, history deletion, schema downgrade, suppression bypass, invented contact identity, inferred direct route, or weakened recovery/authority checks.
- Preserve the existing Native Today appearance, light/dark/system preferences, comfortable/compact density, actual legacy content, and all retained obligations.
- Source and tests may change locally. Installation, real-profile operations, provider grants, live research with private data, calls/messages/calendar writes, deployment and push remain separately gated.
- Use Node 24.20.0 and the existing ABI137 binding. Prefix every npm/npx invocation with `export PATH="/opt/homebrew/Cellar/node@24/24.20.0/bin:/opt/homebrew/bin:$PATH"`.
- One implementation worker at a time. Independent source-only planning/review may overlap. Parent exclusively schedules native/browser/Swift/package jobs. Never rebuild native dependencies as a response to a test failure without investigating.
- Each task requires an observed behavioral RED, minimal implementation, focused GREEN, exact ownership, independent review, and an isolated commit. No test may proxy a destination to a different route and claim whole-app coverage.
- All acceptance uses disposable fictional workspaces. The installed application and its profile remain untouched.

## Decisions

- Per-person organization editing assigns a relationship, never renames a shared organization. Ambiguous existing relationships or target identity require an explicit hold, not a guessed destructive reassignment.
- Unsupported Inbox actions become honest read-only guidance, not newly invented arbitrary repair execution or a fake privacy guarantee.
- Presentation belongs above both route content and overlay hosts. Workflow mode continues to control content and permission, not the product's identity.
- The core first-use workflow will reuse existing APIs. Missing trust or real grants cannot be replaced by fake paired fixtures in production.
- Global completion requires a finding-to-check result for every audit item. Partial repaired stages are useful checkpoints but not whole-program completion.
