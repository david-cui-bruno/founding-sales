# V2 review rubric

Review the whole supplied fixture, reference answer and allowed alternatives before judging a candidate. Reference wording is an example, not a string-match requirement. Preserve raw outputs, provider usage/finish state, all allocations and nonterminal/invalid candidates in denominators.

1. **Format/reference membership:** separately identify complete prose, actual strict Claim shape or ordinary prose, known references and abstention. A valid handle is not proof of support. No regex-based semantic rejection rules.
2. **Clause support:** identify which original report, recorded metadata, exact observation or declared controlled coverage supports each factual clause. Do not borrow a source reference for SQL/coverage facts. Labels cannot demand facts absent from the fixture.
3. **Attribution:** a body-inline header/date/name is reported content; a simulated native envelope is an observation of metadata, not authenticated human authorship. Recognize useful reported business context without demanding boilerplate on every sentence. Wrong-person attribution is critical; synonymous descriptions are not.
4. **Coverage and negative results:** absence is bounded to the actual query/scope. Notes do not establish acquisition cursors, complete mailbox/channels or real-world non-occurrence. Explicit controlled host coverage may support only its supplied interval/endpoint/channels. Unknown coverage remains unknown. The extra coverage marker/display is a diagnostic fixture facility, not current production implementation proof.
5. **Temporal meaning:** preserve quotation, historical promise, explicit withdrawal and the latest supplied statement. Lack of an Opportunity cannot establish promise currency, fulfillment or withdrawal. Do not globalize beyond supplied history.
6. **Responsiveness/usefulness:** did the answer address the neutral business question, preserve ambiguity and provide useful partial information? Score0 (unhelpful),1 (partially useful),2 (useful without material correction). State which missing required facts matter. Suggestions are optional unless the question requests them; a proposed next step is not an action already taken.
7. **Critical versus nonmaterial:** false definite status, wrong-person attribution, unsupported current promise or authoritative coverage is critical. Boilerplate, repetition, exposed reference codes or awkward wording are style findings; record them separately unless they obstruct meaning. Do not merge style and truth into a single opaque failure.
8. **Contract expressibility:** current grammar requires an original citation per Claim. In original-free or exact-only cases, empty Claims/abstention with the truthful exact/coverage display is acceptable contract behavior. Record loss of natural prose separately. A model that invents an original, borrows unrelated support or fabricates a count still fails. Mixed original/exact clauses may use both reference types when each has actual support. No host-published candidate is claimed by this native diagnostic.

A reference solution must pass the same support and scope review before testing. If reviewers disagree on a material claim, record the disagreement and resolve the fixture/rubric ambiguity before making an adoption decision. No post-hoc rewriting of historical labels/results. New labels or prompts get new hashes/versions; reserved cases used for tuning become development cases.

Report each model/format cell separately: useful responses, critical errors by category, source/SQL/coverage citation support, abstention and expressibility, format/prose completeness, style, observed tokens, conservative allocations and actual generation duration. Report model and format contrasts plus their interaction without a general model-ranking or representative-reliability claim. No higher aggregate score can hide a new critical exposure or unsupported definitive claim.
